# 广告过滤规则聚合项目（adblock-dns-aggregator）设计

- 日期：2026-11-12
- 状态：已实施（2026-11-12）
- 定位：通用开源项目（别人可 clone、改配置、PR），同时服务作者自己的路由器
- 文档位置：仓库 `docs/`，设计与实现说明的唯一来源

## 1. 背景与目标

现有的省事做法是直接引用 `217heidai/adblockfilters` 的 mosdns 专用产物，不足有三：

1. 不做父域折叠 —— mosdns 的 `adblock_set` 是**域名后缀匹配**，清单里同时有 `doubleclick.net` 和 `ads.doubleclick.net` 时后者是死条目，白占内存和加载时间；
2. 白名单处理不了 —— 拦截集里有父域、想放行某个子域时，纯 URL 清单无法表达；
3. 源组合与更新节奏全受制于上游。

项目目标：

1. 从**一手**规则源汇总，产出 mosdns 纯域名 / AdGuard `||d^` / dnsmasq / smartdns 四种格式、lite / full / cn / mini 四档的域名清单（cn 为国内源档，mini 为精编中文小档）；
2. 在"后缀匹配"语义下做**父域折叠**（可开关）与**白名单优先扣除**；
3. 每日由 GitHub Actions 构建，发布到专用 `output` 分支，产物落在 `raw.githubusercontent.com` 上，可被路由器的 URL 直接引用（含 `gh-proxy` 前缀）。

非目标：

- 不复刻 AdGuard Home 的完整过滤语法（正则、通配、元素隐藏、`$` 修饰符）；
- 不做命中统计、不做客户端侧服务，只生产清单；
- 不把二手聚合源（如 217heidai）作为默认源 —— 自建聚合器再聚合别人，来源是黑盒；
- 不输出 hosts 格式（第三方工具精确匹配语义下折叠会改变效果，留给后续扩展）。

## 2. 匹配语义前提

四种目标格式在域名维度上都是**后缀匹配**：

| 格式 | 写法 | 语义 |
|---|---|---|
| mosdns `adblock_set` | `example.com` | 默认 `domain:` 后缀匹配 |
| AdGuard | `\|\|example.com^` | 域名及其子域 |
| dnsmasq | `address=/example.com/0.0.0.0` | 域及其子域 |
| smartdns | `address /example.com/#` | 域及其子域 |

因此 `d` 覆盖 `*.d`。这条推论是整个设计的支点，带来两个硬约束：

1. **无法用后缀拦截表达的规则一律丢弃，不降级猜测**。`||d^$third-party` 若降级成 `||d^`，会把"仅第三方"放大成"全量拦截"；`/regex/`、`*.d`、含 `*` 的模糊规则同理。丢弃比误杀便宜。
2. **白名单必须优先于折叠**。见 5.5。

## 5. 处理链

### 5.1 下载

并发 `concurrency` 个请求，UA 固定标识项目名，`timeout` 秒超时，失败重试 `retries` 次；支持 gzip。**单源失败只记录并跳过**，不让整轮作废（这与 mosdns 自带的 all-or-nothing 更新相反，CI 里没有"半成品上线"的问题，因为发布前有哨兵）。

### 5.2 解析

每行先 `strip`，空行 / `!` / `#` / `[Adblock Plus]` 之类头部整行跳过。然后按源声明的 `format` 解析，混入的 hosts 行按形态兜底识别（行首是 `0.0.0.0`、`127.0.0.1`、`::`、`::1` 加空白即按 hosts 处理）。

| 输入形态 | 处理 |
|---|---|
| `\|\|d^` / `\|\|d` | include.add(d) |
| `\|\|d^$mods` | **丢弃**（修饰符不可表达，降级成 `d` 会从"部分拦截"放大成"全量拦截"） |
| `@@\|\|d^` / `@@\|\|d` | exclude.add(d) |
| `@@\|\|d^$mods` | **去掉 `$` 修饰符后仍记入 exclude**（例外方向宁可放宽，误放行比误拦便宜） |
| `domain:d` | include.add(d)（Cats-Team 的 mosdns 前缀格式） |
| `full:d` / `keyword:…` / `regexp:…` | **丢弃**（`full:` 无法用后缀精确表达，降级会扩大拦截面） |
| `0.0.0.0 d` / `127.0.0.1 d` / `:: d` / `::1 d` | include.add(d) |
| 纯域名 `d` | include.add(d) |
| `*.d` / 含 `*` 的其它形态 | **丢弃**（无法表达"仅子域"） |
| `/regex/` / 含 `/` 的非 URL 行 | 丢弃 |
| 保留名（`localhost`、`localhost.localdomain`、`broadcasthost`、`ip6-*` 等） | 丢弃 |
| 域名位置是 IP 字面量 | 丢弃 |

### 5.3 归一化

小写、去行尾 `\r`、去尾部点、非 ASCII 用标准库 `str.encode('idna')` 转 punycode，校验标签长度与总长（≤253），标签合法字符 `[a-z0-9_-]`，至少两级。归一化后重复即自然去重。

### 5.4 档位与例外

- `lite` 集合 = `tiers` 含 `lite` 且 `enabled: true` 的源；
- `full` 集合 = 所有 `enabled: true` 的源；
- `cn` 集合 = `tiers` 含 `cn` 且 `enabled: true` 的源（默认 anti-AD + AWAvenue），供国内用户单独订阅；
- `mini` 集合 = `tiers` 含 `mini` 且 `enabled: true` 的源（默认 AdGuard 中文过滤 + AWAvenue），供内存紧张的路由器使用；
- **例外集合 = 各源的 `@@` 并上 `whitelist.txt`，各档共用**。例外不因档位裁剪而失效。

国内/国外按**源**划分而不是按域名判定：社区中国域名表对本项目 lite 清单只命中约 3.8%（广告域名多挂在 `.com` 或 CDN 下），TLD 与域名级归类误差都不可接受；源级拆分是近似，但来源可解释、维护成本低。

### 5.5 白名单扣除（始终生效，不受折叠开关控制）

对例外集合里的每个 `w`，从拦截集中删除所有 **`d` 是 `w` 的祖先或等于 `w`** 的条目（`d == w or w.endswith('.' + d)`）；同时删除 **`d` 是 `w` 的子孙** 的条目（`d.endswith('.' + w)`）——白名单在后缀匹配下对子域同样生效。兄弟子域不受影响。

原因：后缀匹配下，只要拦截集里有 `example.com`，白名单里的 `a.example.com` 照样被拦。折叠关掉也一样，所以这条不能跟着开关走。

**顺序不可颠倒：本步必须在折叠之前。** 先折叠会把被父域覆盖的子域条目提前删掉，等父域再被白名单顶掉时，那些子域就永久丢失了。

语义取舍明确写死：**宁可漏拦，不可误杀**。父域被白名单顶掉后，其下未被白名单覆盖的子域条目如果本来就在清单里（来自别的源），会保留下来继续生效。

### 5.6 父域折叠（开关，默认开）

`config.yaml` 的 `fold` 或 CLI `--fold/--no-fold` 控制。算法 O(n log n)：

1. 每个域名反转标签顺序（`ads.example.com` → `com.example.ads`）；
2. 按反转串**升序**排序，单遍扫描，维护"最后保留的条目"：当前条目以 `last_kept + '.'` 开头则丢弃（它是上一条的后代），否则保留并更新。

反转排序保证同一祖先的所有后代连续出现，单指针即可判定，不需要 trie。`manifest` 记录折叠前后条数。

### 5.7 输出（8 个文件 + manifest）

| 文件 | 内容 |
|---|---|
| `mosdns-{mini,cn,lite,full}.txt` | 纯域名，一行一个 |
| `adguard-{mini,cn,lite,full}.txt` | `\|\|d^`，头部 `!` 注释 |
| `dnsmasq-{mini,cn,lite,full}.conf` | `address=/d/0.0.0.0` |
| `smartdns-{mini,cn,lite,full}.conf` | `address /d/#` |
| `manifest.json` | 见 5.8 |

所有文件头部注释包含：生成时间（UTC）、档位、折叠开关、条目数、源清单摘要。条目排序固定（反转串序），保证同输入产出字节一致，便于 diff。

文件名全部带来源/格式前缀 —— mosdns 的 `update_adlist` 按 URL 的 basename 落地到 `/etc/mosdns/rule/adlist/`，同名会互相覆盖。

### 5.8 manifest.json

```json
{
  "generated_at": "2026-11-12T20:00:00Z",
  "fold": true,
  "sources": [
    {"name": "hagezi-light", "status": "ok", "entries": 88123,
     "excluded": 12, "bytes": 3123456, "sha256": "...", "duration_ms": 4210}
  ],
  "outputs": [
    {"file": "mosdns-lite.txt", "count": 142301, "previous": 148002}
  ]
}
```

`status` 取值 `ok` / `failed`（下载失败）/ `empty`（解析出 0 条，视同失败）。`previous` 取自上一版 manifest，哨兵和人工排查都靠它。

## 6. CI 与发布

`.github/workflows/build.yml`：

- **触发**：`schedule` 每日 `0 20 * * *`（UTC，北京 04:00）；`workflow_dispatch`；`push` 命中 `sources.yaml`、`whitelist.txt`、`config.yaml`、`aggregator/**`、`tests/**`。
- **手动入参**：`fold`，类型 `choice`，取值 `default|on|off`。`default` 回落到 `config.yaml`（单一事实来源），`on/off` 只覆盖这一次运行。定时触发永远读配置。
- **步骤**：`checkout` → `setup-python 3.12` → 安装 `requirements.txt` 与 `pytest` → `pytest` → 取上一版 `manifest.json` → `python -m aggregator --out dist --previous-manifest …`（按入参加 `--fold/--no-fold`，哨兵在构建步骤内完成）→ Step Summary → 发布。测试失败则不构建，构建或哨兵失败则不发布。
- **权限**：`permissions: contents: write`，发布用 `GITHUB_TOKEN`，提交身份 `github-actions[bot]`。
- **并发**：`concurrency.group: build`，`cancel-in-progress: false`，避免两次发布交错。
- **发布**：切到 `output` 分支（不存在则建 orphan），清空后拷入 `dist/`，单提交，`git push --force origin output`。**强推只作用于 `output` 这一个专用分支**，`main` 只收人工提交。
- **哨兵**：构建前先从 `output` 分支取上一版 `manifest.json`；任一产物条数低于 `previous × min_retain_ratio`（0.8）即构建步骤失败、不推送，旧产物原样保留。这是防"上游改格式导致解析出 0 条"的唯一有效手段。
- **可观测**：Step summary 输出每源状态/条数/耗时/失败列表，以及两档折叠前后条数；红了不用翻原始日志。

## 7. 许可证策略

- `sources.yaml` 的 `license` 字段**必填**，构建时校验存在性，缺了就报错。
- 只收录允许再分发的源（MIT / BSD / Apache / GPL / CC-BY-SA）。
- CC-BY-NC / CC-BY-ND 类源默认 `enabled: false` 并在 README 注明原因 —— 产物是公开发布的，NC 源放进来是对整个仓库的风险。
- README 维护一张表：源名称、仓库地址、许可证、条数、更新频率。
- 代码部分 `LICENSE` 用 MIT；产物不主张额外权利，文件头注明"编译自以下源，著作权归各原项目"。

`pytest`，全部离线（`tests/fixtures/` 下的小样例源），不依赖网络：

- `test_parse.py`：5.2 表格的每一种行形态各一条，含修饰符丢弃、`@@` 带修饰符仍进 exclude、`domain:`/`full:` 前缀、混合 hosts 行、大写、尾点、punycode、保留名、IP 字面量、非法标签；
- `test_fold.py`：父域折叠正确性（`com` / `com.b` / `com.bx` 的相邻性边界）、白名单为子域时父域被删、白名单为父域时子域删除、跨源去重、空集、**关掉折叠时白名单仍生效**；
- `test_emit.py`：四种格式逐行比对（含头部注释与排序稳定性）；

## 9. 使用方式

mosdns（AN7581，`ad_source` 填 URL，`github_proxy` 已配 `https://gh-proxy.com`）：

```
https://raw.githubusercontent.com/DenzelVincent/adblock-dns-aggregator/output/mosdns-lite.txt
# 国内源档
https://raw.githubusercontent.com/DenzelVincent/adblock-dns-aggregator/output/mosdns-cn.txt
# 精编小档（内存紧张）
https://raw.githubusercontent.com/DenzelVincent/adblock-dns-aggregator/output/mosdns-mini.txt
```

AdGuard Home：订阅 `.../output/adguard-full.txt`。
dnsmasq：`conf-file=/etc/.../dnsmasq-lite.conf`。
smartdns（MT7981）：`conf-file /etc/.../smartdns-lite.conf`。

> 由于 mosdns 的 `update_adlist` 在任一 URL 下载失败时会整轮放弃，且按 basename 落地，同一份清单不要同时加两个格式文件。

## 10. 已知风险

| 风险 | 应对 |
|---|---|
| 上游改格式导致解析出 0 条 | 单源 `status: empty` + 哨兵 20% 双保险 |
| 白名单与折叠语义冲突 | 白名单优先，祖先域一律出局，宁可漏拦 |
| 强推不可逆 | 只作用于 `output` 分支；`main` 不参与发布 |
| 许可证漂移 / NC 源误入 | `license` 必填校验 + NC 默认关闭 + README 表格 |
| 折叠开关误用导致体积暴涨 | manifest 记录开关与前后条数，关一次即可量化 |
| 产物文件名冲突（mosdns basename 落地） | 文件名带格式前缀，仓库内唯一 |

## 11. 施工顺序（供实施计划参考）

1. 仓库骨架 + `.gitattributes` + `LICENSE` + 空 `config.yaml`/`sources.yaml`；
2. `parse.py` + 单测（先把最脏的部分钉死）；
3. `fold.py` + 单测（白名单冲突用例优先）；
4. `emit.py` + 单测；
5. `main.py` 编排 + manifest + 离线 e2e；
6. `build.yml`：测试、构建、哨兵、发布；
7. README（源表、用法、许可证）；
8. 首次全量跑通并核对 `output` 分支产物。
